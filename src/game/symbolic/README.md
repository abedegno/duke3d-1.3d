# Equivalent GAME source backend (candidate)

GAME.S is readable named mnemonic source derived first from a fresh build of
this project's ordinary GAME C, then reconstructed against observed native
value flow for wallswitchcheck, spawn, and checkcommandline. It is not claimed
to be the unique historical C text. The C counterpart retains the original
3D Realms/Matt Saettler copyright, GPL notices, public types and readable
algorithms. The three assembly implementations and compiler-shaped register
allocation remain a C humanization backlog. Nonemitting numeric EQU constants
name actual fields, tile values and frame homes; instructions are never stored
as byte arrays. The CODE data directives are the genuine C automatic initializer
templates and typed case-pointer tables. GNU selectors choose real equivalent
instruction encodings; there is no object or image patching.

The whole namespace retains 109 real public definitions, 337 imports and the
eight true private source definitions. Other real local control-flow, literal,
table and template labels also retain qualified section/value identities.
Section-relative lowering does not export any private symbol or assign it an
external target anchor. The separately assembled existing game_tail.asm owns
six genuine public BSS objects, 15 bytes, and must follow this main object.
The main object's 4160-byte BSS range is not proof of every historical palette
or compiler-private name. Unobserved historical TEMPWALLPTR/DMVAL spelling and
palette-name roles remain unresolved. No fabricated aliases are introduced.

The genuine shutdown source order is CONTROL_Shutdown_ then KB_Shutdown_. The
old accepted partial proof had those imported names swapped; that historical
proof is invalidated. Seventy-seven unrelated intervals are unchanged; Shutdown
is reproved with actual admitted provider exports. The resulting 81 complete
CODE intervals cover 84142 bytes and 5018 real relocation fields. The main
object also owns CONST4274, DATA864 and BSS4160. Its seven post-NUL CONST residue
positions remain zero. Full target equality, coverage acceptance, historical
source identity and final executable equality are therefore false.

The tracked contract model contains source/definition/operand coordinates,
real scalar/literal declarations, metadata, typed relocation roles and hashes;
it contains no instruction payload. Listing/ELF/COFF/native checks bind every
field to the entire source operand, rejecting canceled competing owners and
section-base substitutions. Native PUBLIC coordinates, segment classes/access,
imports, groups and unique complete relocation-field bijections are checked.

The fixed source-built GNU profile uses the reviewed defined-global and unused
import forks plus explicit source-owned DGROUP and omission of only the three
unused automatic GNU default sections. Genuine empty CONST2 remains. No default
profile is changed. This profile does not implement the later packet policy.
Build provenance contains complete GNU, decoder and GA assembler tool homes,
Python/emulator identities, live-before-copy/staged/input/output checks. The
producer does not read the target, SDK/game objects, callers or research builds.

Source-only build after normal tool setup:

```
python3 tools/build_game_symbolic.py --build build/game-symbolic-source \
  --report build/game-symbolic-source.json
```

The ordinary C source and its existing producer remain separate and unchanged.
The GNU object emits no Watcom default-library comments; the actual C linkage
requirements clib3r, math387r and emu387 remain explicit final-link obligations.
The C counterpart is an aid, not another link node with duplicate definitions.
