# GF1DMA and GF1UTILS source-native backends

The ordinary C sources and prior C-family routes remain available. `gf1_dma` and
`gf1_utils_native` are separately named reconstructed symbolic backends, with
readable C counterparts and original vendor notices retained. Their assembly is
authored recovery, not claimed published FORTE assembly or a matching C compiler.
The producer consumes tracked source, headers, notices and pinned public-source
GNU tools; original library and executable reads occur only in the observer.

`make proof-gf1-dma proof-gf1-utils-native` builds fresh children and then verifies
all initialized storage, BSS and native fields against the original executable.
DMA retains five genuine private identities and four same-module calls resolved
without loader fields: 89 native fields account for all 93 original roles.
UTILS retains two private identities and all 26 original fields. Its actual empty
BSS alignment is DWORD rather than the old C producer's empty PARA contribution;
this changes native link layout, not the accepted byte-coverage union.

The seven old DMA C intervals cover 653 bytes and 54 roles. The complete backend
covers those same bytes using 51 fields plus three resolved calls, and adds 572
CODE bytes. The old partial proof dictionaries are retained as C history; they
are not counted again. UTILS adds no coverage. Public nominations come from
fresh complete normal DIGITAL and GUS source proofs; private symbols never become
anchors or public exports.

The finite module guards close source operands, ELF/COFF field bijections, full
native public coordinates and segment metadata, live/staged input identity and
whole tool homes. GNU COMENT metadata is honestly different from the historical
C producer; the original math387r/emu387 requirements remain declared for final
linking. Complete module proofs do not establish historical member selection,
final layout or whole-executable identity. C humanization remains unfinished.
